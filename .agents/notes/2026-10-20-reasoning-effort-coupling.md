# 决策：换路由必须同时确定推理档位（2026-10-20）

状态：生效

## 问题

只改写请求的 `provider` / `model`、不动 `reasoningEffort` 时，部分模型会硬失败：

```
pi-ai provider "cpa-trae" model "trae/glm-5.3-flash" does not support reasoning effort "high"
```

## 决策

换路由时，按顺序把候选档位逐个交给适配器验证，第一个通过即采用：

1. 规则里点名的 `reasoningEffort`
2. 模型自己声明的默认档
3. 模型声明的每个档位
4. `off`
5. 完全不发 effort（仅显式允许时）

全部失败则保留继承路由，把原因写进探针与界面。

## 替代方案（强制）

- **只清掉 effort（`delete reasoningEffort`）**：不成立。`cpa-*` 路由在 profile 上带路由级默认档（`REASONING_DEFAULT = 'high'`），清掉请求值等于回落到它。
- **固定映射一张「模型 → 档位」表**：模型清单会变，表必然过期；且适配器才是唯一权威。
- **失败就重试下一个模型**：静默换模型会让用户指定的路由被悄悄替换，违背意图。

## 影响

- 收益：任选渠道都不会把子会话打死；不可用组合在界面里给出可读原因。
- 收益：`trae/glm-5.3-flash` 这类「不声明档位 + 路由默认 high」的冲突被明确暴露，而不是变成神秘失败。
- 代价：每次换路由多几次适配器验证调用，属本地同步计算，可忽略。
