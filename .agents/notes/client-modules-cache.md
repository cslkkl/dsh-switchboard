# 依据：客户端模块清单缓存判空即永久跳过

状态：生效

## 背景

排查「插件已启用、宿主端点 200，但浏览器里没有本插件的界面」时，需要确认清单从哪来、为什么会缺项。

## 结论

- 浏览器端模块清单由宿主启动时扫描 `dsh.client` 段得到，运行时不再重扫。
- `client-modules` 按 `sourceKey(行名, 解析基准)` 缓存「这一行有没有 client 包」。
- 缓存写入 `null` 之后**永不重试**（`resolveMeta` 里的 `pkgMeta.set(key, null)`）。
- 触发条件：`dsh plugin remove` / `add` 正在重写 `node_modules` 时宿主启动，本行被判为「没有 client 包」。
- 无效的补救：改文件 mtime、禁用再启用、宿主热重载 —— key 没变，命中同一份缓存。
- 有效解法：**再重启一次**，且确保安装/卸载动作已经结束。

症状对照片：

| 观察点 | 现象 |
|---|---|
| `/plugins/??` 清单 | 无本包 |
| `window.__DSH_BOOT__.entries` | 无本包（数量比预期少 1） |
| `/plugins/dsh-child-model/client.js` | 404 |
| 宿主 HTTP 端点 | 200，功能正常 |

## 支撑的决策

- 运维口径：安装或卸载插件后，等动作结束再启动，不在同一秒启动。
- 排查顺序：先看 `__DSH_BOOT__.entries` 有没有本包，再看服务端返回，避免误判为代码错误。

## 影响

- 该结论依赖 `client-modules` 当前实现；若上游改为失败重试，本条失效，届时标 `状态：已归档`。
- 已写入根 [AGENTS.md](../../AGENTS.md) 活跃坑，避免重复踩。
